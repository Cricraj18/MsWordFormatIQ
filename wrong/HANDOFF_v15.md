- How xml_rewrite works: names are QUALIFIED ("w:pStyle", "w:val"), unlike xml.ts. A transform gets every token and must call emit() for each token it wants in the output (emit nothing = drop; emit extra = insert). Self-closing tags arrive as open then close. The serializer writes <a/> when a close follows its open at once, so inserting children into an empty element works. The XML declaration and comments come through as "raw" tokens. CDATA comes out as escaped text. Any DOCTYPE throws XML_ENTITY_EXPANSION. Damaged XML throws ZIP_READ_FAILED with detail "partName: message". Errors thrown inside the transform come out unchanged (so CANCELLED or TIMEOUT can be thrown from it).
- It works on strings, not zip entries. For a zip part: read with streamEntry from zipio.ts, decode with TextDecoder("utf-8", stream), call rewriter.write(piece), then end(). Collect the output pieces into a Blob and add it to the zip (check zipio.ts: addText takes a string; for very large parts a streaming add may be needed, to decide in 3b and test).
- Caution for 3b: the transform must track depth itself (to know it is inside a top-level paragraph, not a text box). Paragraph index numbering in 3b MUST match readParagraphs (same rule as pass 2 of structure_detect.ts), or styles will land on the wrong paragraphs. ## DESIGN DECISIONS FOR 2a (made and tested in chat 9)
- Two streaming passes over word/document.xml: pass 1 builds a size histogram weighted by characters (headings, titles, table text and empty paragraphs are left out) and takes the most common size as body size; pass 2 classifies each paragraph and calls back. Nothing large is kept. Cost is about 2 x the XML read time (about 15 MB/s; not measured at 200 MB).
- Only top-level paragraphs count; paragraphs inside text boxes are skipped. Text from w:t only, cut at 300 characters. isListItem only from numPr on the paragraph itself (a list set only by a style, or numbering.xml, is NOT read).
- Rule order (first match wins): table; empty; Word style (Heading N, Title, Subtitle, Quote, Source Code) 0.95; outline level 0.9; caption text or Caption style; labeled heading (Chapter, Part, Unit, Section = level 2, Annexure, Annex, Appendix, Schedule); numbered heading ("1 Intro" 0.7, "2.1 Scope" 0.85, +0.1 if bold or big); list-item 0.9; big bold short line (title 0.7 near the start, heading 0.65); big not bold 0.5; bold at body size = unknown 0.35; else body 0.85. Below 0.6 means manual tagging.
- Known limits: no font-family rule for code (only style names); no centered-line rule; localized "Heading" style names only caught through the outline level or the styleId pattern; real Word/LibreOffice/Google Docs files not tried.
