## DESIGN DECISIONS FOR 2a (made and tested in chat 9)
- Two streaming passes over word/document.xml: pass 1 builds a size histogram weighted by characters (headings, titles, table text and empty paragraphs are left out) and takes the most common size as body size; pass 2 classifies each paragraph and calls back. Nothing large is kept. Cost is about 2 x the XML read time (about 15 MB/s, so a 200 MB document.xml is about 25 s; not measured at that size).
- Only top-level paragraphs count; paragraphs inside text boxes are skipped. Text from w:t only, cut at 300 characters. isListItem only from numPr on the paragraph itself (a list set only by a style, or numbering.xml, is NOT read).
- Rule order (first match wins): table; empty; Word style (Heading N, Title, Subtitle, Quote, Source Code) 0.95; outline level 0.9; caption text or Caption style; labeled heading (Chapter, Part, Unit, Section = level 2, Annexure, Annex, Appendix, Schedule); numbered heading ("1 Intro" 0.7, "2.1 Scope" 0.85, +0.1 if bold or big); list-item 0.9; big bold short line (title 0.7 near the start, heading 0.65); big not bold 0.5; bold at body size = unknown 0.35; else body 0.85. Below 0.6 means manual tagging.
- Known limits: no font-family rule for code (only style names); no centered-line rule; "Heading" styles with other languages' names (for example localized Word) are only caught through the outline level or the styleId pattern; real Word/LibreOffice/Google Docs files not tried.
