## How apply works (decisions, tested)
- Output = TEMPLATE root rels, docProps, styles, theme, fontTable, settings, webSettings, headers/footers (+ their rels and media), numbering merged; SOURCE word/document.xml rewritten (chain: numId remap -> restyle -> section fixer -> field watcher); SOURCE parts reached from kept source document rels (closure follows the parts' own rels), renamed with src_ prefix on clashes; footnotes/endnotes/comments get numId remapped; template body images are NOT copied (only parts reachable from template-owned rels and root rels). [Content_Types].xml is written first; rels default and document override are ensured; overrides for missing parts are pruned. If the template has no numbering part but the source has lists, apply adds word/numbering.xml (or numberingN.xml), a rel "tplNumbering" and an override.
- settings.xml gets w:updateFields only when options.format.updateFieldsOnOpen is true AND the document has fields (fldChar, fldSimple, instrText); otherwise Word would show a pointless prompt. Report warns that fields may look empty until updated.
- Source page size, margins and section breaks are kept per section (landscape stays). All source sections get the template's first header/footer reference set (limit until 5a).
- Source settings, styles, theme, fonts, headers, footers, docProps are not carried over (report warning). Document title from source is NOT copied (not built).
- Memory: output document.xml is collected into Blobs of about 1M characters; non-document parts are read into a Blob one at a time. Not tested with a huge file.
- Known limits: UTF-16 XML parts, source parts re-encoded as UTF-8 text only for footnotes/endnotes/comments when a list map exists; w:sectPr inside tracked changes handled by removing source refs only.
